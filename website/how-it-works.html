How it works

Mailboxes, storage, and the two ways mail reaches an agent.

Paseo Mail is a first draft. Anything marked planned is designed but not implemented yet.

Mailboxes

Each agent has a mailbox, resolved from its name or its role at send time. Senders do not need to know agent ids, and do not wait for an answer.

Durable mail

Messages are written to storage on the daemon before mail_send returns, so a busy agent, an agent that has not started, or a daemon restart does not lose them. planned

Delivery

  1. Turn start. When an agent's turn begins, the plugin adds its unread mail to the context. planned
  2. Idle nudge. When an agent is idle with unread mail, the plugin sends a short nudge so it reads its mailbox. The nudge is idle-only: while a turn is running nothing is sent, and the mail waits for the next turn start. planned

Why not interrupt?

Interrupting a running turn throws away the agent's work in progress. Mail lets agents coordinate without that cost.

Paseo Mail is a plugin for Paseo. Source on GitHub.
