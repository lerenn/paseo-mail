Addresses

  • <name>: the one live agent that registered the name. Names are unique.
  • role:<role>: every live agent holding the role in the sender's workspace, else in its project, else anywhere. Each gets its own copy.
  • agent:<agent id>: that live, non-archived agent, whether or not it registered. Meant for a parent mailing a child it just created. An unknown or archived id is an error. Ids are case-sensitive.
  • Names and roles are lower-case: 1–64 characters a-z, 0-9, ., _ or -.

Tools

ToolInputWhat it does
mail_registername?, roles?Claim or change your name and roles. name: "" releases the name, roles: [] clears the roles, and no arguments shows your registration.
mail_directorynoneList registered names and roles.
mail_sendto, subject, bodySend mail to a name, role:<role>, agent:<agent id>, or a list of them. No name is needed to send. The result tells you to use a recipient's name from now on, and warns if you have no name, since recipients cannot reply by alias.
mail_listunread_only?, limit?List your mail, newest first, without bodies. Needs a registered name; without one it refuses and gives the count of waiting mail.
mail_readidRead a mail and mark it read. Needs a registered name (a role alone does not count).
mail_replyid, bodyReply to the sender, in the same thread.

Delivery

  • Idle nudge: when an agent is idle and has unread mail it was not told about, the plugin sends it a one-line nudge. It never interrupts a running turn, and never wakes an agent again for mail it has read or was already told about.
  • Unread count: every mail tool result ends with Unread: N; for an agent with no name it adds that it cannot read until it registers.
  • Alias required to read: mail stays stored under the agent id and appears untouched once the agent registers a name. The nudge for an agent with no name says so and asks it to register, read, and reply so the sender learns its alias.
  • Durable: mail is stored in $PASEO_HOME/plugin-data/paseo-mail/ and survives restarts.
  • Mail rule: new agents get a short rule in their system prompt: use mail for all non-urgent communication with other agents, and interrupt with a direct prompt only when it is urgent. It is enforced only by the prompt, and agents created before the plugin was installed do not get it.
  • Sidekick mailbox: a project's paseo-playbooks Sidekick (label playbooks/sidekick) gets the mailbox <project-name>-sidekick with the role sidekick. Agents that need a human decision mail role:sidekick (agent id, run/playbook, question, facts, recommendation); without a mailbox they send a direct prompt to the agent found with paseo ls -g.
  • Bounces: unread mail to an agent that is archived goes back to its sender as Returned: <subject>.

Mail screen

  • Open it from the Mail row in Paseo's sidebar.
  • Mailboxes: every agent with a registration or mail. The number is the mail its agent has not read. Archived agents are listed under Archived, with how much of their mail was returned.
  • Mail list: newest first. Bold means no human has opened it; unread means its agent has not read it; returned means it bounced.
  • Reader: the whole thread, oldest first, with when each mail was read by its agent or the agent was told about it. Mark as not opened makes a mail bold again; Open agent opens the recipient's chat.
  • View only: a human cannot send, reply or mark mail read for an agent.
